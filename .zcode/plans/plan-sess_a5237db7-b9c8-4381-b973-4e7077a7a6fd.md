# Separate Borrowed / Recurring Create-Edit Modals — Committed Money

Reference first: `SendMoneyAwayModal.svelte` (the Lending create/edit modal) is the exact visual/UX template — same structure, class system, spacing, amount formatting, date handling, buttons, responsive + dark-mode treatment. `BorrowedMoneyModal.svelte` will be a faithful mirror with only terminology/semantics changed. No new modal design invented.

## 1. NEW `src/lib/client/components/BorrowedMoneyModal.svelte`
Mirror of `SendMoneyAwayModal.svelte` with borrowed semantics:
- Props: `open`, `onClose`, `onSuccess()`, `lendingRecord` (presence = edit mode). Type: `Lending & { cash_paid?, written_off?, payments? }`.
- Header: badge `MONEY COMMITTED`, title `Add Borrowed Money` / `Edit Borrowed Money`, subtitle, close X — same layout/styles.
- Fields (same order/styles as reference): WHO DID YOU BORROW FROM? (`borrower_name`, required) → HOW MUCH? (₱ pill input, comma formatting, hidden raw `amount` carrier) → Date Borrowed (`date_lent`, required, defaults today on create; hidden `date_lent` carrier so a locked input still posts — same mechanism as the Lending modal) → WHEN IS IT DUE? (`due_date`) → Interest (optional) + Note (optional) row → `record_as_transaction` checkbox ("Record repayment as expense transaction when paid") → single dynamic CTA (`Record ₱1,500 Borrowed` / `Update ₱1,500 Borrowed`).
- Payment lock preserved: when `cash_paid + written_off > 0` (or `payments.length > 0`), amount + date borrowed inputs are disabled with the reference's `.field-hint` lock message (mirrors the current LendingForm borrowed lock; server ignores these fields when payments exist).
- Form: `method="POST"`, `action={lendingRecord ? '/borrowed?/update' : '/borrowed?/create'}` with `use:enhance`, hidden `direction=borrowed`, hidden `id` on edit. Absolute action so it posts to the Borrowed actions regardless of current path. Server contract untouched (`borrower_name, amount, interest_rate, date_lent, due_date, notes, direction, record_as_transaction` on create; `id, ...` on update).
- Accent: `--color-money-committed` (#D97706) replacing the Lending modal's sky-blue; everything else (focus rings, glow shadows, 480px responsive tweaks, dark-mode variants) mirrored. Adds the family's `submitting` state (disabled CTA + label swap) and `max-height: calc(100dvh - 40px)` scroll so it works on mobile too.

## 2. `src/lib/client/components/MoneyCommittedModal.svelte` → Recurring-only
Remove the combined-modal behavior: delete `initialMode`/`mode` state, the Scheduled/Debt toggle bar (markup + styles), the entire debt form branch, and debt state/handlers. The scheduled (recurring) form, validation, and `/api/recurring` JSON submit stay exactly as-is.

## 3. `src/lib/client/components/CommittedMoneyWorkspace.svelte`
- **Add CTA**: labeled header button in the switcher row — `+ Add Borrowed` (view=borrowed) / `+ Add Recurring` (view=recurring), opens the correct dedicated modal via `handlePrimaryAdd`. The desktop-only floating FAB and its styles are removed. Empty-state labels updated to match.
- **Borrowed create/edit**: `handlePrimaryAdd` (borrowed branch) and `handleEditBorrowed` open `BorrowedMoneyModal` with/without `lendingRecord`; `onSuccess` = close + `invalidateAll()`. Remove the `SlideOver` + `LendingForm` block and imports.
- **Recurring edit**: `handleEditRecurring` opens a `ModalDialog` (size="wide", title "Edit Recurring Transaction") wrapping the existing `RecurringForm`, posting to the existing `/recurring/{id}?/update` action — all recurring fields/validation/edit functionality reused unchanged. The `/recurring/[id]` deep-link page remains untouched and working.
- **Recurring create**: `MoneyCommittedModal` (now recurring-only); drop `initialMode` wiring.
- Everything else untouched: switcher, `?view=` URL handling, filters, pagination, bulk delete, import/export, payment/history modals, duplicate/pause/run-now handlers.
