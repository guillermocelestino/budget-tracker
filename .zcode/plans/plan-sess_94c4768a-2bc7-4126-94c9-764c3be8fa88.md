# Fix: Committed Money (Borrowed / Recurring) desktop filter toolbar clipping

## Root cause

The desktop filter popover lives in `SearchFilterPill.svelte` (`.filters-popover`, lines 202–217) as `position: absolute` anchored to the Filter button, rendered inline in the toolbar. On the Committed Money page that toolbar sits inside `.table-card-wrapper.flip7-card` (`CommittedMoneyWorkspace.svelte:631`), and **both** the component CSS (line 1232) and the global `.flip7-card` class (`variables.css:444`) set `overflow: hidden`. The popover (380px wide, up to `70vh` tall) is therefore clipped at the card's bottom edge whenever it extends past it — short result lists, empty states, smaller windows — cutting off lower filter items (Category select, Date options, the sticky Reset/Apply footer). `z-index: 1000` cannot help: `overflow: hidden` clips descendants regardless of z-index.

This affects both Borrowed and Recurring views (they share the same `SearchFilterPill` instance with view-specific panels). The toolbar row itself is fine — the pill is block-level and fills the toolbar, with Search → Filter already in the required priority order; no other controls exist in the toolbar (actions live in the header `OverflowMenu`), so no layout/wrapping changes are needed there.

## The fix (1 file): `src/lib/client/components/SearchFilterPill.svelte`

Switch the desktop popover from absolute to the project's established viewport-clamped fixed pattern (already used by `TransactionFilterToolbar.svelte`, `LendingFilterToolbar.svelte`, and `RowActionsMenu.svelte` — none of which have this clipping problem):

1. **CSS — `.filters-popover`:**
   - `position: absolute` → `position: fixed`; remove the static `top / right / left` offsets (set inline by JS).
   - Add `visibility: hidden` by default + a `.positioned` modifier that sets `visibility: visible` (mount hidden → measure → clamp → reveal, exactly like `.filter-popover.visible` in `TransactionFilterToolbar.svelte:500–509`; no position flash).
   - Keep everything else identical (width `min(380px, calc(100vw - 32px))`, `max-height: 70vh`, internal `overflow-y: auto`, cream surface, shadow, `z-index: var(--z-modal, 1000)`, `fade-in-up` animation) so the visual design is unchanged.

2. **Script — positioning logic** (adapted from `TransactionFilterToolbar.positionPopover`):
   - On open (desktop only), after `tick()`: measure the Filter button with `getBoundingClientRect()` and the popover with `offsetWidth/offsetHeight` (layout size, immune to the entrance-animation transform), position it **right-aligned to the Filter button** (preserving today's `right: 0` anchor) with the same 8px gap below, then clamp: horizontally to the viewport with an 8px gutter, vertically flip above the button / clamp if it can't fit below — so the full panel incl. Apply/Reset footer is always reachable even over an empty/short table.
   - Reposition on `resize` and `scroll` (capture) while open, added/removed alongside the existing outside-click/Escape effect; reveal (`positioned = true`) only after clamping.

3. **Unchanged on purpose:** mobile path (≤768px uses the fixed-position `FiltersSheet` bottom sheet — untouched), outside-click/Escape/focus-return logic, `.pill-filter` anchor, both filter panels' markup, the toolbar layout, the card, and all backend/filtering logic. The other `SearchFilterPill` consumers (transactions/lending mobile-only; categories page, which is *not* inside an overflow-hidden card) either don't use the desktop popover or only become more robust with viewport clamping. Verified no ancestor on these pages has `transform`/`filter` (the dark-theme hover-transform gotcha exists only on the transactions card, not this one), so `position: fixed` escapes the clipping correctly.
